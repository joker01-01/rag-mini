# 发布备注：封面建议与排版建议

## 标题备选

1. 《我把自己的资料库变成了一个能问答的 AI：最简 RAG 实践》（正文当前使用）
2. 《任意文件 → Markdown → DeepSeek：一个最小可用 RAG 系统的完整拆解》
3. 《不微调、不训练：用开源工具搭一个"只读我自己资料"的 AI 助手》

## 封面建议

- **风格 A（科技感）**：深蓝/深灰渐变背景，中央一条从左到右的发光箭头，起点是文件图标，终点是聊天框。可用 Canva/稿定设计快速拼，或用 AI 配图生成"知识库 + 机器人问答"的抽象插画。
- **风格 B（极简）**：白底，居中大标题 + 一行小字"任意文件 → Markdown → 检索 → DeepSeek"，箭头用品牌色。适合技术号一贯的克制风格。
- 配图文字不要超过 12 个字，公众号封面在列表页会被裁成 2.35:1。

## 排版建议

- 正文小标题保持简短（6~10 字），段落不超过 4 行；
- 代码块建议在公众号编辑器里用代码样式，行内代码保持浅灰底；
- "实测对比"部分建议保留引用编号 `[1]`，并在文末加一句"引用编号对应检索到的资料片段，可溯源"；
- 数据流图（rag_flowchart.png）建议放第二节，作为全文主线；
- 文末引导语可加："后台回复 RAG，获取完整工程代码"（如果愿意公开仓库）。

## 换真实资料后的更新步骤

1. 把真实文档放进 `docs/`（建议 2~5 份、至少两种格式）；
2. 运行 `python build_kb.py --rebuild` 重建向量库；
3. 运行 `python compare.py` 重新生成"裸问 vs RAG"对比；
4. 把 `results/compare.md` 里的新结果替换进文章"实测"章节，参数保持真实即可。
